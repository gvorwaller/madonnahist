### Key Technical Insight
The four text-improvement tables serve different roles: `ocr_vocabulary` = soft hints ("these words exist"), `correction_lexicon` = learned error patterns ("OCR keeps misreading X as Y"), `notation_key` = hard substitutions ("(R) always means Rebekah"), `day_corrections` = human truth. The first two feed the LLM prompt as guidance; notation_key and high-frequency lexicon entries should be applied as deterministic post-processing, not left to LLM judgment. Separating the substitution pass from the LLM worker means you can re-apply rules without burning Claude API credits.

**Substitution engine bug fix**
- Problem: lexicon rule "Seminar → Seminary" matched as substring, so "Seminary" became "Seminaryy" on each re-run
- Fix: alphanumeric patterns now get `\b` word boundaries in the regex, so "Seminar" only matches the standalone word
- Notation patterns with special characters (e.g. "(R)") skip boundaries since `\b` doesn't apply at non-word edges
- Makes re-runs idempotent

### Files Modified

### Key Technical Insight
Regex `\b` (word boundary) is the right guard for alphanumeric token substitutions — it prevents "Seminar" from matching inside "Seminary". But `\b` sits between `\w` and `\W`, so it won't fire at the edge of patterns containing non-word characters like parentheses. The `isAlphanumeric()` check selectively applies boundaries only where they make sense.
