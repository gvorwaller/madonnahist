### Key Technical Insight

1. **Database-level invariant enforcement beats policy enforcement.** Putting "human truth wins" into role grants + SECURITY DEFINER triggers means a buggy worker (or app) can't silently corrupt `corrected_text` — they get a permission error at the boundary. The whole V4 schema design rests on this: workers connect as `madonnahist_worker` with no UPDATE on `calendar_days.corrected_text`; the trigger fires with `madonnahist_owner` privileges to do the propagation. Code review can't enforce this; the database does.

2. **Generated `tsvector` columns can't include subqueries.** This is a hard PostgreSQL limit. The solution: a `search_aux_text` column maintained by a trigger on `day_tags` and `day_entities` (concatenating tag labels + entity display names), included in the generated FTS column on `calendar_days`. Single GIN index serves text + tag + entity search.

3. **GRANT can't express row-predicate restrictions.** "Worker can INSERT only where `source='ai'`" requires RLS with `WITH CHECK`, not a column-level grant. Codex's finding #4 in round 1. Worth flagging as a class of bug to watch for in any SQL-grants design — table-level INSERT permission is an unconditional power, not a scoped one.

4. **Open-time vs save-time writes need different paths.** Session-tracking columns (`current_session_id`, `editing_started_at`, `last_opened_*`) belong on the day-open `UPDATE` path; save-event columns (`correction_status`, `review_note`, `corrected_text`) belong on the `day_corrections` insert path with conditional trigger propagation. Conflating them was the source of one of Codex's round-2 findings.

5. **Append-only history + denormalized read-cache is the right archive pattern.** Every OCR run, LLM draft, and human save is preserved in its own table; the canonical `calendar_days` row points at the "latest" via FK pointers; triggers maintain consistency. For an archive of irreplaceable family records, the ability to reconstruct any prior state is non-negotiable.
