# 2026-06-05 Devlog

## 21:45 EST - Correction UI Enhancements: Review Navigation, Substitution Fix, Day Narrative

### Summary
Several correction UI improvements in one session: fixed the substitution engine's substring over-matching, added month day-list view and prev/next navigation so Madonna can review and re-edit corrected days, and added the day narrative field for capturing memories alongside transcriptions.

### What Was Done

**Substitution engine bug fix**
- Lexicon rule "Seminar -> Seminary" was matching as a substring, causing "Seminary" to become "Seminaryy" on each re-run
- Fix: alphanumeric patterns now get `\b` word boundaries in the regex; notation patterns with special characters (e.g. "(R)") skip boundaries since `\b` doesn't apply at non-word edges
- Makes re-runs idempotent

**README.md & CLAUDE.md housekeeping (td-887e96, closed)**
- Phase 1 marked complete, pipeline diagram updated, family viewer removed from active surfaces
- Fixed stale `madonnahist_user` references, enumerated admin routes, updated tech stack and env vars

**Month day-list view (`/correct/month/[monthKey]`)**
- New route showing all days for a month with status badges and corrected text previews
- Month cards on `/correct` now always link to month view (no more disabled state)
- Madonna can see what's corrected and tap into any day to review or re-edit

**Day editor navigation overhaul**
- Added Prev/Next links that walk ALL days in the month (not just uncorrected)
- Kept "Next uncorrected" links with green styling, separated by a divider
- Breadcrumbs: Queue / January 2022 — both clickable
- Save on an already-corrected day shows "Save" (not "Save & Next") and stays on the same day

**Day narrative field**
- Added `day_narrative` textarea below corrected text in the day editor
- Warm-toned styling (border: `#c4b5a0`, background: `#fdfcf9`) to visually distinguish from the correction field
- Saved via direct UPDATE on `calendar_days` (not through `day_corrections` trigger path — per V4 spec, no append-only history needed)
- DB columns already existed from migration 0012; just needed UI and save logic
- Month view shows "N" badge next to days that have narrative content
- Dropped the "expanded text" field from the V4 spec — redundant since Madonna already expands abbreviations in her corrections and the substitution engine handles notation

### Key Technical Insight
The V4 spec's "expanded text" field (field 4) assumed Madonna would preserve shorthand notation in corrected text and spell it out separately. In practice, she already writes readable text in the correction box, and the substitution engine pre-expands notation in the LLM drafts. So expanded text is redundant — the only new field worth adding is day narrative (field 5), which captures genuinely new content: memories and context not on the page. This is the family history gold.
