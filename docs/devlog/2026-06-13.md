# 2026-06-13 Devlog

## NAS Spaces Backup and Local Image Protection

### Summary

Set up a NAS-side backup path for the Madonna History DigitalOcean Spaces
objects, cleaned up unused NAS storage, added lightweight snapshot retention,
verified restore behavior, and committed sanitized operational scripts and docs
to the repo.

The immediate goal was to protect the production calendar image assets now that
pre-generated day crops exist in Spaces and represent hours of real ingestion,
alignment, OCR, and correction work.

### What Was Done

**Volume 3 Spaces backup share**

- Created a dedicated DSM share for Madonna History Spaces backups on NAS
  Volume 3:
  - Share name: `madonnahist-spaces-backup`
  - Path: `/volume3/madonnahist-spaces-backup`
- Configured it as a NAS-pull backup from DigitalOcean Spaces using `rclone`.
- Installed `rclone` locally for the NAS admin user under the user's home
  directory rather than adding system-wide package dependencies.
- Stored the NAS-local rclone config outside the git repo with private Spaces
  credentials in the NAS admin user's config directory.

**Backup behavior**

- The NAS pulls from the `madonnahist` Spaces bucket into:
  - `/volume3/madonnahist-spaces-backup/current/pages`
  - `/volume3/madonnahist-spaces-backup/current/crops`
- The backup uses `rclone copy --checksum --fast-list`.
- It intentionally copies missing/changed objects from Spaces to NAS but does
  not delete local NAS files just because an object disappeared remotely.
- This is conservative for image protection: accidental remote deletion should
  not immediately propagate as local deletion.

**Schedule**

Added NAS cron entries:

```cron
15 3 * * * NASADMIN /volume3/madonnahist-spaces-backup/backup-spaces.sh >> /volume3/madonnahist-spaces-backup/logs/spaces-cron.log 2>&1
15 4 * * * root /volume3/madonnahist-spaces-backup/snapshot-spaces-backup.sh
```

This runs the Spaces pull daily at 03:15 NAS local time, then takes a snapshot
at 04:15.

**Snapshot retention**

- Added ordinary Synology/Btrfs snapshots for the backup share.
- Retention is intentionally small: keep the latest 2 snapshots.
- Snapshots are not immutable/WORM snapshots.
- This gives a short recovery window for mistakes without turning the NAS into
  a long-term snapshot archive or creating unnecessary local file bloat.

  - `/volume3/madonnahist-spaces-backup/manifests/`
- Restore drills:
  - `/volume3/madonnahist-spaces-backup/restore-drills/`

The NAS pull model is preferred over routing Spaces backups through the Mac:

- It does not depend on the Mac being awake.
- It avoids making CCC responsible for cloud object synchronization.
- It keeps the NAS as the durable local copy of production image assets.
- It leaves CCC and future Arq jobs focused on Mac-local configuration, source
  files, and selected user data.
