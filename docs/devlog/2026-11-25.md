## Find duplicates: one plain question per name (td-7e0d72)

Gaylon found the Find duplicates cards confusing. Each name had a checkbox, a "Keep this name" radio, "Alias of X" and "Not the same", and each card had a "Keep X" radio, "Merge ticked…", "Check with Claude" and "Skip for now". "Alias of" and "Merge ticked" did nearly the same thing.

### What changed

Each name now asks one question, **Same person as "X"?**, with two answers:
- **"Yes, same person…"** opens a confirm box naming every name involved. Its "Show as" choice picks the surviving spelling; the main name is chosen unless you change it. Confirming merges the names.
- **"No, different"** takes effect at once. It can be undone from the "Marked not the same" list.

Not sure means leaving the name alone.

The card actions are:
- **"All N are the same …"**: shown when two or more names could merge. N counts the main name.
- **"Ask Claude"**: hidden once nothing is left to ask.
- **"Not sure: skip for now"**.

**Suggested answers.** The suggested answer is the filled button. It follows Claude's verdict when Claude has been asked; otherwise "Yes" is filled for very likely matches. Nothing is suggested for a name with days outside the main name's years, because those days need reading first.

**Removed:**
- the checkboxes and "keep" radios;
- "Alias of…" and "Merge ticked…";
- the cleanup page's `?/alias` action. Setting an alias by hand still works on `/admin/entities`, and its invariant tests now go through `?/setAlias` there.

Kept:
- moving single days;
- the evidence check that refuses a merge when entries changed since the page loaded;
- whole-card merges. Merging one name changes the main name's days, which drops Claude's answers for the rest of that card.

### Review

CODEX9 found six problems over three rounds. All are fixed, each with a Safari test:
- the confirm box could run off a short screen; it now scrolls inside itself;
- a check returning "changed" while the box was open still allowed confirming. The box now says so and disables "Yes";
- focus fell to the page body when "Ask Claude" disappeared. It now goes to the card heading, unless another control has focus;
- the confirm text claimed every name is searchable, which isn't true for Events; it now describes what is guaranteed;
- "All 2" opened a three-name merge.

## Find duplicates: no zero-day matches; jump links and folding sections (td-a7920d)

Gaylon corrected a day from "J S Paige" to "Joy School with Paige" and came back via "Back to Find duplicates". Re-extraction had dropped the link, so "J S Paige" now had 0 days. The page still offered it as a match for "Paige", with Yes/No buttons that meant nothing and nothing to read.

### What changed

- **The matcher** (`src/lib/entity-matcher.ts`) never pairs a name with no days, either as the main name or as a candidate. Such a name shows under **Unused** with Delete. It still appears on `/admin/entities` if it has aliases, moved days, a map decision or a "not the same" mark.
- **"Jump to: Possible duplicates (N) · Unused (N) · Marked not the same (N)"** sits under the tabs.
- **Each section is a `<details>`**:
  - Duplicates start open; the other two are folded.
  - A jump stays a real link, so the address gets `#sec-<name>`, a reload keeps it, and a modified click opens a new tab.
  - A jump opens the section before the browser scrolls, then focuses its `<summary>`, so Enter folds it again.
  - Focus moves a task later, because the fragment navigation would otherwise take it away in Safari. SvelteKit runs no afterNavigate for in-page hash links.
- **The `#g-<id>` back link** reopens the duplicates section if it was folded.

### Review and tests

CODEX9 found two problems:
- after a jump, focus was on the h2, so Enter didn't fold the section;
- `preventDefault` kept the address from changing.

Both are fixed, and CODEX9 says it's clean.
