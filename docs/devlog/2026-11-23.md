## Find duplicates: /admin/entities/cleanup (td-c6e871)

The extractor makes a new entity for every spelling it sees, so duplicates pile up (Rebekah / Rebekah Lynn / Rebeky, Gayon / Gaylon, K-Mart / Kmart). Fixing that by hand would take hours and wouldn't get done. The plan is `docs/2026-11-23-entity-cleanup-plan.md`; Gaylon's decisions:
- Claude pre-check on demand: per group, or "check the next 20".
- Moving single days between names is included.
- Nothing ever merges automatically.

### What shipped

**Grouping.** A pure matcher (`src/lib/entity-matcher.ts`) groups each type's canonical names around a main name. A pair matches on:
- the same letters;
- a one-letter typo of a much commoner name;
- a close spelling;
- a first name of a fuller one.

Names whose digits differ are never paired. The name fold is shared with `/admin/entities` (`src/lib/name-fold.ts`).

**Group cards.** Each card shows each candidate's count, years and entries (lazy `EntityMentions`). A span warning flags a candidate with days outside the main name's years, the hint that one name covers two people.

**Claude check.** "Check with Claude" (one group) or "Check the next 20" asks Claude whether each pair is the same, with a short reason. The answer is stored with a fingerprint of the exact names, days and text it saw, so a later rename, move or re-extraction can't revive it. Claims stop two tabs paying for the same pair.

**Merging.** Merge several ticked names into a chosen survivor, confirmed in a modal. The page sends the fingerprints it showed. The merge re-checks them after taking the graph, day and row locks, and refuses with "changed since this page loaded" if anything moved. Links move in one statement.

**Other actions.**
- **"Not the same":** the pair is never suggested again, and a merge that would join it is refused. The mark carries to the survivor on merge.
- **Moving one day's link** to another name also leaves a day block. The enrichment worker skips blocked links, so re-accepting the day doesn't put it back.
- **Unused names** (no mentions, no "not the same" mark) are offered for delete.

**Migration 0036** adds three tables:
- `entity_not_same`;
- `entity_cleanup_checks`;
- `day_entity_blocks` (the worker can only SELECT it).

**Smaller changes.**
- `/admin/entities` counts a main name's distinct family days.
- Places: `decided_at` marks a human decision. Recheck never overwrites one, and "No map" upserts through the canonical-write guard.

## Relay: wake log shows Codex's real error (td-b460f3)

Codex wakes for CODEX9 were failing with only "exited with code 1". Running `codex exec --json` directly showed the cause was the account usage limit. Gaylon had moved to the $20 plan; he upgraded again.

Codex reports account errors as stdout events, not stderr, so the runner never logged them. `scripts/run-codex-delegate.js` in claude-relay now logs them to `logs/wake-peer.log`:
- what's logged: `error`, `turn.failed` and notice events;
- format: one timestamped, labelled line each, control characters squashed, capped at 2,000 characters, deduped.

The final failure is classified from the untruncated text. A usage limit records the fixed reason `usage_limit` and exits 78 (no retry), so the monitor names it plainly. No provider text reaches the failure file.

CODEX9 review: clean. Committed 6acc1da on `wake-log-provider-errors`, merged into `~/claude-relay` main and pushed. It's a runner script, so it's live at once with no restart.
