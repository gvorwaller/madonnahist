### Key Technical Insight
- **Version checks have to cover every action, not just save.** A stale tab's Unshare succeeded,
  the page then reloaded fresh data, and its next Save went through with the new version and
  overwrote newer text.
  - The edit page keeps its own `loadedVersion`. It only moves forward after the page's own
    successful action.
  - A refused save hands back the version the text was submitted with, so a re-render without JS
    still pairs the text with the right version.
- **Default privileges from 0004 also apply to new sequences.** Revoke the sequences as well as
  the tables, then grant only `USAGE`.
- **An explicit `INSERT` of id 1 doesn't move a `SERIAL` sequence forward.** Call `setval` before
  inserting the next row.
- **`TRUNCATE users CASCADE` also empties `writers`.** After that, the default writer id on
  `calendar_pages` (1) points at a row that's gone, so test fixtures must re-seed writer 1.
