### Current pipeline understanding

The production OCR pipeline is:

1. Google Vision performs the first full-page OCR scan against the aligned or
   warped page image.
2. Words are mapped into day cells using the saved grid lines.
3. Claude performs day-by-day cleanup using the per-day crop plus the Google
   Vision raw text.
4. Human corrections remain authoritative and are stored through
   `day_corrections`; machine outputs do not overwrite accepted human text.

The new crop feature pre-generates day-cell crop JPEGs once per current
`grid_version` and stores their keys in `calendar_days.day_image_path`. Serving
routes now prefer those stored crop objects instead of repeatedly rendering
crops on demand from full-page images. Geometry-changing operations must clear
or delete stale crop paths and regenerate current ones:

- grid save
- warp apply
- warp reset
- page replacement
- un-ingest cleanup

This is intended to reduce Sharp work, memory spikes, and repeated crop-render
latency while preserving the on-demand fallback when a crop path is absent.
