## 20:35 EST - Places: stricter matching, re-check, map picker, Google key (td-085e19)

### Summary
After the first production run of place auto-matching, about 20 of 91 automatic maps were wrong (chains, one-word names, far-away namesakes). Shipped a stricter rule (v2) that re-decides old automatic rows from stored candidates, plus an admin Google map picker for fixing any place by hand. Deployed as b815ed0, and the Maps browser key now allows madonnahist (production and local 5177).

### What Was Done
- **Matching rule v2** (`src/lib/server/place-rules.ts`, pure, unit-tested):
  - Whole-phrase name match (K-Mart = Kmart, filler words like "Utah"/"City" skipped).
  - Street matches only when the place name starts with a number.
  - Tails like "Provo, Utah" must agree with the address (state abbreviations mapped).
  - Rivals more than 2 km apart, or two businesses, mean "several": no map.
  - One-word names near home go to Needs a look unless exact, an area, or a natural feature.
  - Far away: only states, countries, and multi-word towns are automatic.
  - More generic words (mini, game room, family, Christmas tree lot, playground, rink…).
- **Re-check:** migration 0030 adds `place_locations.rule_version`. At startup, rows decided automatically by an older rule are re-decided from stored candidates (no Google calls). Rows with `decided_by` set are never touched.
- **Admin `/admin/places`:**
  - "No map for this place" became **Don't show a map**.
  - New **Find on map / Change on map** picker (`LocationPicker.svelte`): native `<dialog>`, full-screen on phones. Search with numbered results and markers, tap a Google business (place details), or tap/drag a pin (reverse geocode).
  - Save posts `?/pin`, which stores the location as confirmed and writes audit `place_location_pin`.
  - New admin-only JSON endpoint `/admin/places/locate` for search, details, and reverse geocode, all server-side with the server key.

### Key Technical Insight
- **Google Cloud changes can be done from Gaylon's own Safari via AppleScript `do JavaScript`, not safaridriver.**
  - safaridriver windows are ephemeral (no Google cookies), and Google blocks sign-in from WebDriver browsers.
  - The everyday Safari window is already signed in and allows Apple Events JavaScript.
  - The Maps key lives in the **vorwaller.net** account (`authuser=1`), project `gaylonphotos`. The other signed-in account cannot see it.
  - Google asked for one passkey confirmation; that was the only step Gaylon had to do.
- **Console inputs are Angular.** Set values through the native `HTMLInputElement` value setter, then dispatch `input`/`change`. Each new website entry needs Add → Done, then Save at the bottom.
- **The browser key's referrer list decides where the map draws.** Until today madonnahist could only render maps locally on trips' port 5179. Use 5177 now.
- **Rule versioning:** storing the top candidates per place made a stricter rule cheap to roll out, with no new API calls.
