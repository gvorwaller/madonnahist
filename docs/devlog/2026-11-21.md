## Signed-out saves (td-46337c)

Before: a form saved after the session had expired did nothing at all. The hook's plain 401 isn't an ActionResult, so `update()` ignored it.

- **Memory editor (`MemoryForm.svelte`):**
  - Says "You've been signed out, so your memory isn't saved yet. It's kept on this device", with a sign-in link back to the same page.
  - The text, the date and the version it was based on are kept in this tab's sessionStorage (`src/lib/viewer/memory-draft.ts`).
  - After sign-in they're put back with "Here's what you wrote… It isn't saved yet" and a **Discard it** button.
  - Only the same account gets it back: on a shared iPad, the next person's visit removes it. It expires after a day.
  - It's dropped as soon as the server answers a save, so a refusal (e.g. changed in another window) behaves as before.
- **Every other form:** a new wrapper `src/lib/forms.ts` around SvelteKit's `enhance`. Every page now imports it, and `npm run test:signed-out` checks that nothing imports `enhance` from `$app/forms` directly.
  - A signed-out answer raises the app-wide bar (`SignedOutBar.svelte` in the root layout): "You've been signed out, so that wasn't saved", with Sign in again and Close.
  - The bar is fixed to the bottom with `role=alert`. Typed fields stay on screen.
  - Forms that already say so themselves (Hide/Show, "Memories you see", the memory editor) opt out with `data-signed-out-inline`.
- Not changed: the correction editor's autosave already shows "Draft save failed" on a 401.

### CODEX review, round 1 (2 P1, 5 P2), all fixed

- **P1, stale text after a conflict:** the edit page now owns the version. A kept edit brings back its base version, and Save, Unshare and Delete all send it (`onrestore`). **Discard it** returns to the server's text and its own version together (`canonical` + `ondiscard`). So a restored stale edit can never overwrite or delete a revision the writer hasn't seen.
- **P2, network failure:** an `error` result (network failure or server error) keeps the text (reason `error`). Coming back shows "Here's what you wrote when saving went wrong. It may not have been saved…".
- **P2, edits after the notice:** while "signed out" is showing, the kept copy follows what's on screen, including edits typed while the save was pending.
- **P2, success-only effects on a 401:** the wrapper now hands pages a signed-out answer as a real 401 **failure** (`form.error` = "You've been signed out, so that wasn't saved."). Pages that clear input or close editors on anything but failure (vocabulary editor, correction tags) now keep what was typed.
- **P2, location picker:** it's a modal, so it handles signed-out inline with its own sign-in link.
- **P2, late answers:** a signed-out answer for a page already left (form removed, or URL changed) raises no bar. The bar's sign-in link is the originating page's.

## td-eb28c8: modal dialogs are native `<dialog>`s

A follow-up from CODEX's td-f1f49b review (finding 13). The confirm modals were `div role="dialog"` overlays, so Tab could reach the page behind and focus wasn't returned on close.

### What changed

- **New `src/lib/components/Modal.svelte`.** It wraps the page's existing overlay markup in a bare, full-screen native `<dialog>` opened with `showModal()`. The look is unchanged.
  - The page behind becomes inert, and Escape calls `onclose`. Chrome's forced close after repeated Escapes is handled through the `close` event.
  - Focus starts on the dialog itself, not a button, so Enter can't confirm by accident and the iPad keyboard doesn't pop up.
  - When the dialog leaves, focus goes back to its opener.
- **New `src/lib/dialog-opener.ts`.** Safari doesn't focus a clicked button, so `document.activeElement` is `<body>` when a dialog opens. A capture-phase click listener remembers the last control clicked (within 1.5 s) as the opener. `modalOpen()` lets page-level Escape handlers leave a modal's Escape alone.
- **Converted 21 dialogs:**
  - Narratives: Publish, Unpublish, Replace published text.
  - Users: Remove access, Delete, Invite link, New/Cancel link, Reset password.
  - Vocabulary: Delete/Suppress, Promote.
  - Entities: Delete, Merge.
  - Exports and Ask: Delete.
  - Capture: Un-ingest and the preview lightbox.
  - OCR review: lightbox.
  - Correction day: Flag illegible, History, Day cell zoom, Full page.
- **Escape handlers:** duplicate window Escape handlers for these modals were removed. Those left for inline editing skip Escape while a modal is open. EntityPicker now `preventDefault`s Escape, so closing its list doesn't close the Merge dialog.
- **Narratives:** Unpublish and "Replace published text" now close on any result (they used to stay open on failure). An error or the signed-out bar is never hidden behind the modal.
- **Focus return for the existing native dialogs:** Places LocationPicker, memory Delete confirm, ImageZoom, and the family Menu drawer. The drawer skips it after following a link.
- **`npm run test:dialogs`** (4 checks): no `role="dialog"` overlays, every `<Modal>` has `onclose` and a name, and every other `<dialog>` restores focus.
