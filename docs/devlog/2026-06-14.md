# 2026-06-14 Devlog

## CCC Postgres Preflight Repair

### Summary

Fixed the Madonna History CCC preflight backup script after two CCC runs failed
with only the generic Carbon Copy Cloner message:

```text
The preflight shell script exited with a non-zero exit code.
```

The project log at `data/backup/preflight.log` showed the real failure:

```text
[backup-pg] prod dump failed pg_restore -l verification
```

This was not caused by the giftlist repo or by production database corruption.
CCC was invoking the correct Madonna History script:

```text
/Users/gaylonvorwaller/madonnahist/scripts/backup-pg.sh
```

The script's PATH assumed Homebrew `postgresql@17` clients existed under:

```text
/opt/homebrew/opt/postgresql@17/bin
```

That opt path no longer had `pg_dump` / `pg_restore` on this Mac. The current
installed clients are available through Homebrew `libpq`, with PostgreSQL 16
clients also present as a fallback.

### Script Changes

Updated `scripts/backup-pg.sh` to:

- Add `/opt/homebrew/opt/libpq/bin` and `/opt/homebrew/opt/postgresql@16/bin`
  to the CCC-safe PATH.
- Log the resolved `pg_dump` and `pg_restore` binary paths on each run.
- Fail clearly if `pg_restore` is missing.
- Treat missing local `pg_dump` as a local snapshot failure/skip path, not as an
  ambiguous production backup failure.
- Verify local dumps before moving them into the final filename.
- Copy the production dump to `madonnahist.pgdump.tmp` first.
- Verify the production dump with `pg_restore -l` before replacing the last
  known-good `madonnahist.pgdump`.
- Preserve the previous production dump if a future pull or verification fails.
- Log the actual verifier stderr on future dump verification failures.

### Verification

Ran syntax and functional checks:

```sh

./scripts/backup-pg.sh
./scripts/backup-pg.sh /System/Volumes/Data/Users/gaylonvorwaller/madonnahist /Volumes/madonnahist ''
```

Both functional runs completed successfully. The local dev PostgreSQL service

```text
[backup-pg] pg_dump=/opt/homebrew/opt/libpq/bin/pg_dump
[backup-pg] pg_restore=/opt/homebrew/opt/libpq/bin/pg_restore
[backup-pg] WARN: local snapshot skipped: local PG not listening on localhost:5434
[backup-pg] prod snapshot ok: /Users/gaylonvorwaller/madonnahist/data/backup/prod/madonnahist.pgdump
```

After the repair, both the Madonna History and giftlist CCC backup tasks were
reported successful.

## NAS Spaces Backup Status and Failure Notification

Enhanced the NAS-side DigitalOcean Spaces pull script with explicit health
artifacts and failure-only DSM notifications.

The script now writes stable "latest" files for live runs:

- `/volume3/madonnahist-spaces-backup/LAST_RUN_STATUS.json`
- `/volume3/madonnahist-spaces-backup/LAST_SUCCESS`
- `/volume3/madonnahist-spaces-backup/LATEST_LOG_PATH`
- `/volume3/madonnahist-spaces-backup/manifests/latest-spaces-rclone-manifest.json`
- `/volume3/madonnahist-spaces-backup/manifests/latest-spaces-source-size.json`

Live failures write `LAST_FAILURE.json` and send a DSM notification through
`/usr/syno/bin/synodsmnotify` to `@administrators` by default. Dry runs write
separate dry-run status files so manual testing does not overwrite the live
backup health state, and dry-run failures do not notify unless explicitly
enabled.
