# 2026-06-06 Devlog

## 21:00 EST - OCR Pipeline Auto-Trigger, Manual Entry Mode, and Admin Fixes

### Summary
Major session: fixed the OCR pipeline to actually run when triggered from the UI, added live progress display, implemented un-ingest/clear-OCR admin controls, built manual entry mode for non-OCR pages, and fixed several bugs found during production testing.

### What Was Done

**OCR worker not running (root cause)**
- OCR jobs were being enqueued to `job_runs` but nothing spawned the worker process
- Anthropic API key was missing from `private_data.api_credentials` — worker read from env, key was only in local `.env`
- Fixed worker to use `getApiKey('anthropic', 'API_KEY', 'ANTHROPIC_API_KEY')` like Google Vision key
- Stored Anthropic key in DB, ran worker manually to process 4 backlogged pages (123 llm_cleanup jobs)

**Auto-trigger OCR from grid-align save**
- New `src/lib/workers/spawn.ts` — spawns OCR worker as detached background process with concurrency guard and failure surfacing
- `saveGrid` action spawns worker when "Re-run OCR after save" checkbox is checked
- `applyWarp` no longer enqueues or spawns OCR — warp is just perspective correction, OCR waits for grid save

**Live OCR progress on OCR review page**
- New `/admin/ocr-review/[pageId]/progress` polling endpoint, scoped to current `grid_version`
- Sticky progress strip: stage 1 (Google Vision) as checklist item, stage 2 (Claude cleanup) as progress bar with day-by-day preview
- Auto-refreshes grid via `invalidateAll()` on completion, stops polling
- Fixed infinite polling bug: `startPolling()` was restarting after `invalidateAll()` triggered reactivity

**Un-ingest a page**
- New `uningest` form action on capture intake — reverts an ingested page back to classified state
- Guards against pages with accepted corrections
- Clears FK before deleting (Codex caught the FK ordering bug)
- Modal confirmation dialog on completed items in the intake UI
- Used to fix the mis-classified Feb→Mar 2010 page

**Clear OCR results**
- New `resetOcr` form action on grid-align — wipes all OCR runs, LLM drafts, and clears calendar_days pointers
- Nullifies `day_corrections.source_llm_draft_run_id` before deleting drafts (Codex caught the FK issue)
- Inline confirmation UI with success banner

**Dead job cleanup**
- Removed per-day `'ocr'` job enqueuing from `src/lib/ingest/ingest.ts` — those jobs were never processed by the two-stage worker and can't run without grid_lines
- Cleaned up stale `job_type = 'ocr'` join in OCR review list page

**Manual entry mode (td-510071)**
- "Next uncorrected" navigation now includes ALL pending days, not just those with OCR drafts
- Correction queue resume includes all pending days
- Day editor shows full page image with red cell-highlight overlay when no draft/OCR exists
- Added `crop_bounds` and page dimensions to the day editor load query for highlight positioning
- Month view and queue labels say "manual entry" instead of "No OCR draft"

### Key Technical Insight
The system was already 90% ready for manual entry — the draft pane hides when there's no draft, save works without a draft, and `populateLexicon` returns early when there's no OCR to learn from. ## 22:15 EST - resetOcr Permission Fix + Production Testing

### Summary
The "Clear OCR Results" button was hitting a 500 because `madonnahist_app` didn't have DELETE on `ocr_runs` / `llm_draft_runs`. Added migration 0016 to grant the permission.

### What Was Done

**resetOcr 500 fix**
- Root cause: `madonnahist_app` role had SELECT/INSERT/UPDATE but not DELETE on `ocr_runs` and `llm_draft_runs`
- Migration `0016_grant_ocr_delete_for_reset.sql` grants DELETE on both tables to the app role
- Deployed and verified migration applied

**Manual entry UX flow documented**
For non-alignable months (squiggly hand-drawn grid lines like January 1994):
1. Page is already ingested with approximate grid alignment
2. Grid-align: get grid roughly close, save with OCR checkbox **unchecked**
3. Correction queue → month view → days show as "Manual entry"
4. Day editor shows full page image with red cell-highlight overlay
5. Type correction while viewing handwriting, Save advances to next day

### Files Modified
- `backend/db/migrations/0016_grant_ocr_delete_for_reset.sql` — **new** grant DELETE on ocr_runs/llm_draft_runs

### Key Technical Insight
The DB role model is strict by design — the app role only gets the permissions it needs, and new admin actions that touch worker-owned tables need explicit grants. The error log on the droplet (`/var/log/pm2/madonnahist.err.log`) showed the exact permission error clearly.
