# 2026-11-24

## Correction day: "Back to Find duplicates" (td-8a7e37)

On Find duplicates, a candidate's entry date opens that day for correction. After fixing it, Gaylon had to go back to Admin, open Find duplicates and find the group again. Now the date link carries `?back=<the group>`, and the day page shows "← Back to Find duplicates" above the breadcrumbs.

### What shipped

- **The way back survives everything on the day page.** It is kept through Save, Skip, Flag and Prev/Next. Form actions use absolute paths that carry `back`; the server wraps each redirect in `withBack`.
- **Returning lands on the group.** It focuses the group's heading and shows more groups when the group is past the first 20.
- **Only known pages are accepted as a back target** (`src/lib/return-to.ts`: Find duplicates with an optional type and `#g-<id>`). Anything else shows no link, so the parameter can't send anyone off-site.

Fixing the day exposed problems with leaving it:

- **Leaving with an unsaved change now asks first:** Save and leave, Leave without saving, or Keep editing.
  - It covers links, the browser's Back and Forward, Done for now, and closing or reloading the tab. Close and reload show the browser's own prompt.
  - On an uncorrected day, a leave first tries to save the draft and only asks if that fails.
- **Accepted days no longer claim "Draft saved".** Autosave doesn't change an accepted day's text, so the status now says "Not saved yet: press Save to keep this change".
- **Autosave always posts to the day being edited.** During browser Back the address bar already shows the previous day, and a relative `?/autosave` had posted the text there.

### Review and tests

CODEX9 reviewed for four rounds, and all findings were fixed:
- the false "Draft saved";
- the dirty-unload gap;
- Back breaking Forward;
- autosave posting to the wrong day;
- a failed Done for now leaving the guard off;
- a confirmed pause re-saving discarded text.
