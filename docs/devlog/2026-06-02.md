## 17:32 EST - Two-Stage OCR Pipeline, Grid Alignment Commit, OCR Review Fix

### Summary
Committed the grid alignment UI + perspective warp (built earlier today), then rewrote the OCR worker from single-pass Claude Vision to a two-stage pipeline (Google Vision full-page + Claude cleanup). Fixed a critical duplicate-rows bug in the OCR review page.

### What Was Done
- **Apply Grid button feedback**: Added `savingGrid` processing state so the button disables and shows "Saving grid..." during submission, matching the existing "Apply Warp" button behavior.
- **Two-stage OCR pipeline** (Codex-reviewed design):
  - **Stage 1 (`page_ocr`)**: Sends the full warped page image (4791x3047) to Google Vision `DOCUMENT_TEXT_DETECTION`. Returns 720 words with bounding boxes in 1.9s. Words are mapped to grid cells using bbox overlap area (not just center point), sorted into reading order via y-baseline line clustering, then reconstructed as per-cell text. Writes one `ocr_runs` row per cell with `vendor_meta` containing word boxes, grid version, and provenance.
  - **Stage 2 (`llm_cleanup`)**: For each cell, crops the day from the warped page, sends Claude Sonnet the cell image + Google Vision raw text + family context prompt (names, activities, places). Writes `llm_draft_runs` linked to the `ocr_runs` row. Empty cells skip the Claude call.
  - **Job queue split**: `page_ocr` (one per page) produces `ocr_runs` + enqueues `llm_cleanup` jobs (one per day). Clean retry semantics — Google Vision call isn't repeated when only Claude cleanup needs retry.
- **Migration 0011**: Fixed unique index on `ocr_runs(created_by_job_run_id)` to `(created_by_job_run_id, day_id)` — one page-level job now inserts up to 31 ocr_runs rows.
- **Google Vision adapter rewrite** (`src/lib/ocr/vendors/google-vision.ts`): Added `transcribeFullPage()` returning word-level bounding boxes, `mapWordsToCells()` with bbox-overlap cell assignment, `wordsToText()` with line-clustered reading order, `sortReadingOrder()` for per-cell word ordering.
- **Grid-align server update**: `cancelAndRequeueOcr()` now cancels `page_ocr` and `llm_cleanup` jobs (not just old `ocr` type) and enqueues a single `page_ocr` job instead of 31 per-day jobs.
- **OCR review page fix**: The `job_runs` LEFT JOIN on `payload->>'day_id'` with `job_type = 'ocr'` produced a Cartesian product (multiple old job_runs per day from grid version bumps). Removed the broken join entirely. Page now shows Claude draft text (from `llm_draft_runs`) with fallback to raw OCR, labeled "draft" or "raw OCR" accordingly.

### Key Technical Insight
The prior Google Vision eval (May 28) only tested on small cell crops (~700x600) and concluded it "garbles proper nouns similarly to Claude Vision." Nobody tested Google Vision on the full page with bounding-box-to-cell mapping. At full page resolution (4791x3047), Google Vision detects 720 words in 1.9 seconds with ~69% average confidence — noisy but character-level accurate enough for Claude to clean up. The two-pass approach plays to each model's strengths: Google Vision for raw character recognition, Claude for contextual interpretation with family vocabulary.

The OCR review duplicate-rows bug was a LEFT JOIN fan-out: `job_runs` had multiple rows per day (from repeated grid saves), and the join on `payload->>'day_id'` with no DISTINCT or LIMIT produced N copies of each day card. With the new `page_ocr` job type (one job per page, not per day), the per-day job join is no longer meaningful — removed entirely.

## 18:05 EST - Grayscale Preprocessing + OCR Review Lightbox

### Summary
Added grayscale + normalize + sharpen preprocessing before OCR to improve recognition of pencil-on-beige handwriting. Added click-to-zoom lightbox to OCR review page for easier reading.

### What Was Done
- **Grayscale preprocessing** (suggested by Marcus): Both OCR stages now convert to grayscale, normalize contrast (stretch to full 0-255), and sharpen (sigma 1.5) before sending to APIs. Previously, raw color camera photos went straight to Google Vision and Claude. Re-ran the full pipeline on page 1 — noticeable improvements: "spagetti" → "spaghetti", "stomac clot" → "clothes weights, stomach", "9 morn" → "& mirror", day 29 much cleaner overall.
- **OCR review lightbox**: Click any cell image to see it full-size in a dark overlay with the draft text below. Close with Escape, X button, or click outside. Uses the same pattern as the capture intake lightbox.
- **Committed and pushed** as `06e71f1`.

### Files Modified
- `backend/workers/ocr-worker.ts` (grayscale + normalize + sharpen at both stage 1 and stage 2 download points)
- `src/routes/admin/ocr-review/[pageId]/+page.svelte` (lightbox overlay, image button wrapper, CSS)
- `src/routes/admin/ocr-review/[pageId]/+page.server.ts` (already fixed in prior commit)

### Key Technical Insight
Google Vision's `DOCUMENT_TEXT_DETECTION` handles color images fine, but pencil on beige calendar paper is inherently low-contrast — the beige background and pencil gray are close in luminance. Grayscale + normalize stretches that narrow contrast range to the full 0-255 spectrum, making letterforms much more distinct. Hard thresholding (true black/white binarization) was considered but rejected — it can clip thin pencil strokes if the threshold is wrong. The grayscale approach preserves gradients while still dramatically improving contrast.
