### Key Technical Insight
The adversarial review caught a real UX trap: `Number('')` silently produces `0`, which is a valid number but matches no dropdown option. The select gets stuck in an unrecoverable state requiring a page reload. Any `<select>` with a placeholder `<option value="">` that feeds into `Number()` has this bug — always guard for the empty string before coercing.

The CODEX review's most valuable finding was the deployment model gap — the plan assumed the server could read `~/Lumix Tether` but production runs on a remote droplet. Making the capture-station model explicit early avoided a class of "works in dev, breaks in prod" issues.

### Key Technical Insight
The CODEX-caught FK ordering bug is a pattern worth remembering: when table A has `REFERENCES table_b(id)` and you want to delete from table_b, you must clear or delete the referencing rows in table A first — even inside a transaction, unless the FK is `DEFERRABLE INITIALLY DEFERRED`. The original code deleted `calendar_pages` before nulling `capture_intake.page_id`, which would abort the transaction every time.

The "upload first, delete+insert in one transaction" pattern for replace operations ensures atomicity without two-phase commit: if upload fails, old data is untouched; if the transaction fails, old data is rolled back intact and the orphaned Spaces object is harmless (same deterministic key reused on retry).
