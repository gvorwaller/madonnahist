Three small improvements to the admin tooling: reorganized the capture intake completed list, fixed a broken API key lookup for classification, and added promoted-status indicators to the correction lexicon.

### What Was Done

- Classify action was reading `GOOGLE_VISION_API_KEY` from process environment (`$env/dynamic/private`)

- Classification had only ever worked locally where the env var was set manually

**Correction lexicon promoted indicators**

### Files Modified

### Key Technical Insight
The classify action's use of `$env/dynamic/private` was a leftover from local-only development. On the droplet, all third-party API keys live in `private_data.api_credentials` (queried via `credentialService`), not in `.env`. This pattern keeps secrets out of filesystem config and centralizes them in the database with `is_active` toggles and audit trails. Any future API integrations should follow the same pattern.

### Key Technical Insight
Svelte 5 warns when reactive `$props()` data is captured outside a reactive context (`$derived`/`$effect`). For one-time initialization like "expand years that need work on first load", wrapping in an IIFE `(() => expr)()` breaks the reactive reference and silences the warning without changing behavior. The `$derived` approach would reset expanded state on every data reload, which is wrong for user-toggled accordion state.
