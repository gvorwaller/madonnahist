# 2026-06-10 Devlog

## 22:00 EST - Capture Intake Polish, Classify Fix, Lexicon UX

### Summary
Three small improvements to the admin tooling: reorganized the capture intake completed list, fixed a broken API key lookup for classification, and added promoted-status indicators to the correction lexicon.

### What Was Done

**Capture intake completed list reorganization**
- Replaced flat filename-sorted list with year-accordion layout (collapsible year bars, same pattern as correction queue)
- Within each year, pages listed by month name (chronological) instead of camera filename
- Added "View" button on each entry that opens the full page image in the existing lightbox (via `/admin/grid-align/[pageId]/page-image`)
- Un-ingest confirmation dialog now shows "March 1991" instead of raw filename
- Purely client-side grouping via `$derived` — no server changes needed

**Google Vision API key fix**
- Classify action was reading `GOOGLE_VISION_API_KEY` from process environment (`$env/dynamic/private`)
- The key was never in `.env` on prod — it lives in `private_data.api_credentials` (service `google_vision`, key `API_KEY`)
- Switched to `credentialService.getCredential()` which already existed for Spaces and Anthropic credentials
- Classification had only ever worked locally where the env var was set manually

**Correction lexicon promoted indicators**
- Lexicon entries whose corrected token exists in `ocr_vocabulary` now show a green "in vocabulary" tag next to the corrected token
- Promote button replaced with green "Promoted" label for already-promoted entries (Suppress still available)
- Built with `$derived` set from vocabulary data already loaded on the page — no extra queries

### Files Modified
- `src/routes/admin/capture/+page.svelte` — year-accordion completed list, View button, lightbox integration
- `src/routes/admin/capture/+page.server.ts` — switched from `env.GOOGLE_VISION_API_KEY` to `credentialService.getCredential()`
- `src/routes/admin/vocabulary/+page.svelte` — promoted tags and label on lexicon entries

### Key Technical Insight
The classify action's use of `$env/dynamic/private` was a leftover from local-only development. On the droplet, all third-party API keys live in `private_data.api_credentials` (queried via `credentialService`), not in `.env`. This pattern keeps secrets out of filesystem config and centralizes them in the database with `is_active` toggles and audit trails. Any future API integrations should follow the same pattern.
