## /admin/entities: fold, find, jump by letter (td-9432c1)

Production has about 2,100 entities (916 people, 405 places, 824 events) on one page. Gaylon asked for three things:
- **Foldable sections:** the People, Places and Events headings are buttons (`aria-expanded`). Which sections are open is remembered in localStorage. The page still works if storage is unavailable.
- **Find a name:** a search bar that stays at the top and narrows all three sections. It matches the name, the slug or the alias target, one field at a time. It ignores case, accents and ligatures (NFKD, marks stripped). A second pass also ignores punctuation and spaces, keeping letters and digits in any script, so "kmart" finds "K-Mart".
  - The match count is shown in a status line, and each header shows "N of M".
  - During a search, sections with a match open and the rest fold. Any section can still be flipped for that search.
  - Clear puts focus back in the box.
- **Letter locator:** rows are sorted A–Z, with "#" (other initials) last. Each letter has its own `<tbody>`, headed by a `th scope="rowgroup"`.
  - A two-column grid of 44px letter buttons sits to the right of each section. It is sticky under the search bar.
  - It comes before the table in the DOM, so Tab reaches it first; CSS grid places it on the right. Under 700px it becomes a row above the table.
  - Clicking a letter scrolls its heading to just under the search bar and focuses it.

The table now sits in a sideways-scrolling wrapper. That would have clipped Set alias's floating list (CODEX). `EntityPicker` gained an `inline` prop that puts the list in the page's flow. Set alias uses it; the Merge dialog doesn't.

CODEX review took three rounds:
- **Round 1, six findings:** the clipped picker; locator keyboard order; search matching across joined fields; zero-match sections that couldn't open; colgroup scope; Clear dropping focus, plus count contrast.
- **Round 2, two findings:** empty-text contrast; initials outside A–Z ("ﬂ" gave "FL"), and the "#" label.
- **Round 3:** clean.

Checks: `npm run check` 0/0. A Safari (safaridriver) run on the test stack with about 2,100 seeded entities passed 36/36 twice; search updates in about 100 ms. The clipped-picker check was confirmed to fail without the fix.
