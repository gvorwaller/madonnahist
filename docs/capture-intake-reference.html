Capture & Processing Workflow — Calendar Archive

G9 II + Lumix Tether → /admin/capture (classify + ingest) → /admin/grid-align (corners + warp + lines) → OCR Worker (Google Vision full-page + Claude cleanup) → /correct (Madonna corrects on iPad) → structured calendar_days
Capture intake runs on your local Mac (reads ~/Lumix Tether). Grid alignment, OCR, and corrections run against the droplet DB and work from any machine. Madonna accesses the correction UI at https://madonnahist.gaylon.photos/correct.

Phase 1: Capture & Ingest

1
Start the dev server: npm run dev — port 5176. Open http://localhost:5176/admin/capture
2
Photograph calendar pages with Lumix Tether. Reload the page to pick up new images.
3
Click "Classify All". Each image gets Google Vision OCR for month/year detection + quality assessment. Takes a few seconds per image.
4
Review each card:
  • HIGH + GOOD — confirm year/month, check the box
  • MED / LOW — set year/month manually, check the box
  • RESHOOT — re-photograph, reload
5
Click "Ingest Selected". Uploads to Spaces, creates calendar_pages + calendar_days rows, enqueues page_ocr job.

Phase 2: Grid Alignment

6
Navigate to http://localhost:5176/admin/grid-align/{pageId} (linked from OCR review). Two-stage process:

Stage A: Place Corners (on original image)

  • Drag 4 corner handles to match the outer boundary of the calendar grid
  • Interior lines auto-subdivide as preview (dashed)
  • Click "Apply Warp" — perspective-warps the image to a rectangle (15–30 seconds for full-res G9 II images)
  • Button shows "Processing warp..." while working

Stage B: Refine Lines (on warped image)

  • After warp, the page reloads showing the de-skewed rectangular image
  • Drag individual grid lines to match actual cell boundaries (solid lines, row/col resize cursors)
  • Live crop preview strip shows sample cells below the image
  • Click "Apply Grid" (shows "Saving grid..." while working) — saves lines, recomputes crop bounds, re-queues OCR
  • "Re-place Corners" resets the warp and returns to Stage A
Copy from Previous Page: If a prior page has been calibrated, a "Copy from..." button appears. Calendar pages from the same brand typically have the same grid layout.

Phase 3: OCR Pipeline

The OCR worker runs as a one-shot script (not PM2). Two stages, run independently:

7
Run Stage 1 (Google Vision full-page):
npx tsx --env-file=.env backend/workers/ocr-worker.ts --stage=page_ocr
  • Downloads full warped page image, converts to grayscale + normalize + sharpen
  • Sends to Google Vision DOCUMENT_TEXT_DETECTION (one API call per page)
  • Maps words to grid cells using bounding-box overlap
  • Writes one ocr_runs row per cell, enqueues llm_cleanup jobs
8
Run Stage 2 (Claude cleanup):
npx tsx --env-file=.env backend/workers/ocr-worker.ts --stage=llm_cleanup
  • For each cell: crops from the warped page (grayscale + normalize + sharpen)
  • Sends Claude Sonnet the cell image + Google Vision raw text + family context prompt
  • Writes one llm_draft_runs row per cell (linked to ocr_runs)
  • ~3 seconds per cell, ~$0.50 per page

Or run both stages together: npx tsx --env-file=.env backend/workers/ocr-worker.ts

Useful flags: --dry-run (claim jobs but skip API calls), --page-id=N (one page only), --limit=N (max N jobs)

Phase 4: Review & Correction

9
Review OCR results at http://localhost:5176/admin/ocr-review/{pageId}
  • Calendar grid of cell images with Claude draft text
  • Click any cell image for lightbox zoom
  • Confidence percentages from Google Vision (yellow = 40–69%, green = 70%+)
10
Madonna corrects at https://madonnahist.gaylon.photos/correct
  • Month list with progress bars — "Resume Correcting" goes to first uncorrected day
  • Two-column editor: cell image (click to zoom, "View full page" for context) + corrected text textarea
  • Save & Next — saves accepted correction, advances to next day
  • Skip — marks as in-progress, moves forward (won't reappear in queue)
  • Flag Illegible — modal with optional note, marks as illegible
  • Accepted corrections auto-populate the correction_lexicon (word-level diffs improve future OCR)

Troubleshooting

"Tether folder not found"~/Lumix Tether doesn't exist. Open Lumix Tether and shoot one image. Or set TETHER_DIR in .env.
"GOOGLE_VISION_API_KEY is not configured"Add to .env and restart dev server. Also stored in private_data.api_credentials for the OCR worker.
Images don't appear after shootingReload the page. Discovery runs on page load.
Duplicate month detectedCard shows warning with old filename. Replace if no corrections; otherwise handle via admin.
Warp takes too long / hangsNormal for full-res G9 II images (15–30 sec). Button shows "Processing warp..." The perspective transform is pure JS bilinear interpolation on ~22M pixels.
OCR worker: "stale grid version"Grid was updated after the OCR job was enqueued. Re-run the worker — it will pick up fresh jobs.
OCR worker: "No pending jobs"All jobs processed. Re-queue via grid-align (check "Re-run OCR" + Apply Grid) or manually INSERT a page_ocr job.
Correction UI: "Not authenticated"The auth stub queries for username 'madonna' in the users table. Verify the user exists: SELECT * FROM users.
DB connection refusedCheck SSH tunnel is running (com.gaylon.madonnahist-db-tunnel LaunchAgent, localhost:5435 → droplet:5434).
Layout says "won't fit"The grid template can't hold the selected month. Try 5-row-wrapped or 6-row-standard.
