Capture & Processing Workflow — Calendar Archive

G9 II + Lumix Tether (Mac) → rsync to DO droplet → /admin/capture (classify + ingest) → /admin/grid-align (corners + warp + lines) → OCR auto-runs (Google Vision + Claude cleanup) → /admin/ocr-review (live progress + results) → /admin/substitutions (notation + lexicon replacements) → /correct (Madonna corrects on iPad) → structured calendar_days
Everything runs on the DO droplet. The only local Mac process is Lumix Tether (camera capture). A LaunchAgent rsyncs ~/Lumix Tether to the droplet every 2 minutes. All admin, correction, and viewer UIs are at https://madonnahist.gaylon.photos.

Phase 1: Capture & Ingest

1
Photograph calendar pages with Lumix Tether. Wait ~2 min for rsync to sync to the droplet.
2
Open https://madonnahist.gaylon.photos/admin/capture — sign in as gaylon. New images appear automatically (discovery runs on page load).
3
Click "Classify All". Each image gets Google Vision OCR for month/year detection + quality assessment. Takes a few seconds per image.
4
Review each card:
  • HIGH + GOOD — confirm year/month, check the box
  • MED / LOW — set year/month manually, check the box
  • RESHOOT — re-photograph, wait for rsync, reload
5
Click "Ingest Selected". Uploads to Spaces, creates calendar_pages + calendar_days rows. OCR does not run yet — grid alignment is required first.

Duplicate Pages

No corrections"Replace Existing" button — atomically swaps old page for new
Has correctionsReplacement blocked — handle via admin to avoid losing Madonna's work

Un-ingest a Page

If a page was ingested with the wrong month/year: expand the "Completed" section, click "Un-ingest" next to the row. Confirm in the modal dialog. The page, days, OCR results, and drafts are deleted; the image reappears in the active intake section for re-classification.

Guard: Un-ingest is blocked if any accepted corrections exist on the page.

Phase 2: Grid Alignment

6
Navigate to https://madonnahist.gaylon.photos/admin/grid-align and select a page. Two-stage process:

Stage A: Place Corners (on original image)

  • Drag 4 corner handles to match the outer boundary of the calendar grid
  • Interior lines auto-subdivide as preview (dashed)
  • Click "Apply Warp" — perspective-warps the image to a rectangle (15–30 seconds for full-res G9 II images)
  • Returns to the grid-align page showing the de-skewed image; OCR does not run yet

Stage B: Refine Lines (on warped image)

  • After warp, the page reloads showing the de-skewed rectangular image
  • Drag individual grid lines to match actual cell boundaries (solid lines, row/col resize cursors)
  • Live crop preview strip shows sample cells below the image
  • Check "Re-run OCR after save" to trigger OCR automatically on save
  • Click "Apply Grid" — saves lines, recomputes crop bounds
  • If OCR was checked: redirects to OCR review page with live progress strip
  • If OCR was unchecked: stays on grid-align with green confirmation banner
  • "Re-place Corners" resets the warp and returns to Stage A
  • "Clear OCR Results" wipes all OCR and draft data for this page (for re-running after grid fixes)
Copy from Previous Page: If a prior page has been calibrated, a "Copy from..." button appears. Calendar pages from the same brand typically have the same grid layout.

Non-Alignable Pages (Hand-Drawn Grid Lines)

Some calendar pages have squiggly, hand-drawn grid lines that can't be precisely aligned. For these:

  1. Place corners and warp as usual — even rough alignment is helpful
  2. Adjust grid lines to approximate the hand-drawn lines (doesn't need to be perfect)
  3. Save the grid with OCR unchecked — OCR won't produce useful results on bad crops
  4. Navigate to the correction queue — these days show as "Manual entry"
  5. The day editor shows a padded cell crop (best guess, with surrounding context) plus the full page image with the current cell highlighted in red
  6. Madonna types corrections while looking at the handwriting on screen

Phase 3: OCR Pipeline

OCR runs automatically when you save grid lines with "Re-run OCR after save" checked. No SSH or manual commands needed. Two stages run back-to-back:

7
Stage 1 — Google Vision full-page scan:
  • Downloads full warped page image, converts to grayscale + normalize + sharpen
  • Sends to Google Vision DOCUMENT_TEXT_DETECTION (one API call per page, ~5–10 seconds)
  • Maps words to grid cells using bounding-box overlap
  • Writes one ocr_runs row per cell, enqueues llm_cleanup jobs
8
Stage 2 — Claude cleanup (per cell):
  • For each cell: crops from the warped page (grayscale + normalize + sharpen)
  • Sends Claude Sonnet the cell image + Google Vision raw text + dynamic family context prompt
  • Prompt assembled from ocr_vocabulary + correction_lexicon + notation_key tables (manage at /admin/vocabulary)
  • Writes one llm_draft_runs row per cell (~2–4 seconds per cell, ~$0.50 per page)

Live Progress

After grid save with OCR triggered, you're redirected to the OCR review page. A sticky progress strip shows:

  • Stage 1: "Google Vision scan — queued / scanning / done (N words, Ns)" or failed with error
  • Stage 2: Progress bar — "12 of 30 days cleaned up..." with latest day's text preview
  • On completion: strip says "OCR complete", grid auto-refreshes to show results
  • "Refresh now" button and "Back to grid" link always available
Manual worker run (if needed for debugging): npx tsx --env-file=.env backend/workers/ocr-worker.ts
Flags: --dry-run, --page-id=N, --limit=N, --stage=page_ocr|llm_cleanup, --show-prompt

Phase 4: Substitution Pass

9
Open https://madonnahist.gaylon.photos/admin/substitutions
  • Shows active rules from notation_key (e.g., “(R)” → “Rebekah”) and high-frequency correction_lexicon entries (freq ≥ 3)
  • Click “Run Substitutions” to apply deterministic find-and-replace on all uncorrected LLM drafts
  • Writes new llm_draft_runs rows (preserves history — original draft is never overwritten)
  • Skips days with accepted corrections (Madonna’s text is sacred)
  • Shows before/after diffs for every modified day
  • Re-run any time after adding new notation or vocabulary entries
Manage rules at /admin/vocabulary — three sections: OCR Vocabulary (family names, places, activities fed to the Claude prompt), Notation Key (shorthand symbols like “(R)” → “Rebekah” used for hard substitution), Correction Lexicon (auto-learned OCR error pairs from Madonna’s corrections).

Phase 5: Review & Correction

10
Review OCR results at https://madonnahist.gaylon.photos/admin/ocr-review
  • Select a page to see calendar grid of cell images with Claude draft text
  • Click any cell image for lightbox zoom
  • Confidence percentages from Google Vision (yellow = 40–69%, green = 70%+)
  • Filter by low confidence or blank cells
11
Madonna corrects at https://madonnahist.gaylon.photos/correct
  • Month list with progress bars — "Resume Correcting" goes to first pending day
  • Click a month to see day list with status badges + text previews
  • OCR'd days: Two-column editor — cell image (click to zoom, "View full page" for context) + machine draft + corrected text textarea
  • Manual entry days: Padded cell crop (best guess with context) + full page image with cell highlight + corrected text textarea
  • Day narrative: Optional textarea for memories/stories this entry brings to mind
  • Save & Next — saves accepted correction, advances to next pending day
  • Save (on already-corrected days) — saves and stays on the same day
  • Skip — marks as in-progress, moves forward (won't reappear in queue)
  • Flag Illegible — modal with optional note, marks as illegible
  • Accepted corrections auto-populate the correction_lexicon (word-level diffs improve future OCR)
  • Manual-entry corrections do not populate the lexicon (no OCR errors to learn from)

Troubleshooting

"Tether folder not found"TETHER_DIR in .env doesn't exist on the droplet. Verify /opt/madonnahist/tether/ exists and rsync has run.
Images don't appear after shootingWait 2 min for rsync, then reload. Check ~/Library/Logs/madonnahist-tether-sync.log on Mac. Manual sync: rsync -avz ...
Preview images blankCheck that source_path in capture_intake is relative (e.g., 20260525/P1034702.jpg), not absolute. Files must exist under TETHER_DIR.
Duplicate month detectedCard shows warning with old filename. Replace if no corrections; otherwise handle via admin.
Wrong month ingestedExpand Completed section in capture intake, click "Un-ingest", re-classify with correct month.
Warp takes too long / hangsNormal for full-res G9 II images (15–30 sec). Button shows "Processing warp..." The perspective transform is pure JS bilinear interpolation on ~22M pixels.
OCR not running after grid saveMake sure "Re-run OCR after save" checkbox is checked before clicking Apply Grid.
OCR progress strip stuckClick "Refresh now" or reload the page. Check ocr-worker.log on the droplet for errors.
OCR results look wrongGo to grid-align, adjust lines, click "Clear OCR Results", then re-save grid with OCR checked.
OCR worker: "stale grid version"Grid was updated after the OCR job was enqueued. Save grid again with OCR checked to re-trigger.
Hand-drawn grid linesAlign as best you can, save with OCR unchecked. Days appear as "Manual entry" in the correction queue. Use the padded crop + full page image to transcribe.
Not authenticated / 403Sign in at /login. Admin pages require the admin role (gaylon). Correction pages require corrector or admin.
rsync failingCheck SSH key auth: ssh root@134.199.211.199 echo ok. Check LaunchAgent is loaded: launchctl list | grep tether.
Layout says "won't fit"The grid template can't hold the selected month. Try 5-row-wrapped or 6-row-standard.
