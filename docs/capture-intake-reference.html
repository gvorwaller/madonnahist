Capture Intake Workflow — Calendar Archive

This runs on your local Mac, not the droplet. The server needs to read ~/Lumix Tether, which only exists on the Mac connected to the camera. The droplet has no access to your tether folder.

Prerequisites

Camera connectedG9 II via USB, Lumix Tether running
Tether folder~/Lumix Tether/ — Lumix Tether writes JPG+RAW into dated subfolders here
DB accessPostgres on the droplet must be reachable from the Mac (check .env has correct PGHOST/PGPORT)
Migration appliedRun ./backend/db/migrate_pg.sh if you haven't since adding 0007
Google Vision keyGOOGLE_VISION_API_KEY set in .env

1. Start the Local Dev Server

1
Open a terminal in the madonnahist project directory and run:
npm run dev
Wait for the "ready" message. The server starts on port 5176.

2. Open the Capture Intake Page

2
Open in your browser:
http://localhost:5176/admin/capture

On load, the server scans ~/Lumix Tether/ subfolders for new JPGs. Any images not already in the database appear in the active list. Already-ingested images are hidden in a collapsed "Completed" section at the bottom.

If you see "tether folder not found" in the header, ~/Lumix Tether doesn't exist. Make sure Lumix Tether has saved at least one image.

3. Shoot Your Pages

3
Photograph calendar pages using Lumix Tether. JPG + RAW pairs land in ~/Lumix Tether/{session-date}/.
Reload the page (or navigate back to it) to pick up newly shot images.

4. Classify All

4
Click the "Classify All (N)" button in the toolbar. This processes every unclassified image:
  • Sends each image to Google Vision for full-page OCR
  • Locates the month/year from the header text using token geometry
  • Assesses image quality (sharpness, exposure, contrast)
  • Takes a few seconds per image — the button shows "Classifying..." while working

After classification, each card shows:

Confidence badge HIGH — month + year detected with good OCR confidence
MED — partial match (year only, or low OCR confidence) — confirm manually
LOW — nothing found — set year/month manually
Quality badge GOOD — sharp, well-exposed, good contrast
RESHOOT — blurry, over/underexposed, or low contrast — reason shown in notes
Year / Month / LayoutPre-filled dropdowns from the OCR proposal. Edit any that are wrong.

5. Review and Correct

5
Go through each card:
  • HIGH confidence + GOOD quality — glance at the thumbnail to confirm, check the box
  • MED or LOW confidence — set the correct year and month from the dropdowns, then check the box
  • RESHOOT badge — read the quality notes (e.g., "Blurry, sharpness 10, threshold 12"). Click Reshoot to flag it. Re-photograph the page, reload, and the new image will appear
  • Accidental shot (wall, floor, test frame) — click Reject
Layout selector: Most calendars are 5-row-wrapped (the default). If a layout can't hold the selected month (e.g., 31-day month starting Saturday in a non-wrapped 5-row grid), the option is grayed out with "won't fit." Pick 6-row-standard if nothing else works. For 4-row calendars with wrapped last days, pick 4-row-wrapped.

5b. Duplicate Pages

If the proposed (or manually selected) year/month already has an ingested page, the card shows a duplicate warning with the old filename and page ID. Two cases:

No corrections on old page Warning reads: "January 1991 already ingested (P1034502.jpg, page #12) — no corrections yet"
A "Replace Existing" button appears. Click it to swap: the old page, its day rows, and its Spaces image are deleted, and the new image is ingested in their place. This is atomic — if anything fails, the old page is untouched.
Old page has corrections Warning reads: "January 1991 already ingested (P1034502.jpg, page #12) — has corrections, cannot replace from here"
No replace button. The checkbox is disabled — you cannot batch-ingest over a corrected page. Handle via admin.
Changing the year or month in the dropdowns will update the duplicate warning in real time. If you change to a month that isn't already ingested, the warning disappears and you can ingest normally.

6. Ingest Selected

6
Click "Ingest Selected (N)". This processes every checked image in one pass:
  1. Uploads the EXIF-normalized page image to DigitalOcean Spaces
  2. Creates calendar_pages + calendar_days rows in the database (one transaction)
  3. Enqueues OCR jobs for each day cell
  4. Moves the card to the collapsed "Completed" section
The button shows "Ingesting..." while working.
If ingestion fails for an image, it stays in the active list with a red error message. You can retry — the upload is idempotent (same image won't be duplicated in Spaces). Fix the underlying issue (e.g., that month already ingested, DB unreachable) and click Ingest again.

7. Verify

7
After ingestion:
  • Ingested images appear under the "Completed (N)" toggle at the bottom, showing filename, year-month, and page ID
  • Reload the page — completed images stay completed, new tether images appear in the active list
  • Repeat steps 3–6 for the next batch of pages

Troubleshooting

"Tether folder not found"~/Lumix Tether doesn't exist. Open Lumix Tether and shoot one image to create it. Or set TETHER_DIR in .env if your folder is elsewhere.
"GOOGLE_VISION_API_KEY is not configured"Add GOOGLE_VISION_API_KEY=... to .env and restart the dev server.
Images don't appear after shootingReload the page. Discovery runs on page load, not live.
Duplicate month detectedThe card shows a warning with the old filename and page ID. If the old page has no corrections, click "Replace Existing" to swap it. If the old page has corrections from Madonna, replacement is blocked — handle via admin.
Classification says LOW / no month foundNormal for handwritten or unusual headers. Set year and month manually from the dropdowns.
"Layout can't hold this month"The selected grid template doesn't have enough slots. Switch to 5-row-wrapped or 6-row-standard.
DB connection refusedCheck that the droplet is reachable. If using an SSH tunnel, make sure it's running. Verify PGHOST/PGPORT in .env.
